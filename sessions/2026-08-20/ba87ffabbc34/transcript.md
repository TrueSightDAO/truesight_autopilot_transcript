## The four terms

| Term | What it is | Who uses it |
|---|---|---|
| **Verra** (you wrote "Vera") | A nonprofit standards organization (HQ Washington DC) that runs the world's largest voluntary carbon programs. They don't issue credits themselves — they set the *rules* and certify projects against them. | Standard-setter / registry operator |
| **VCS** | **Verified Carbon Standard** — Verra's flagship program. Projects validated under VCS earn tradable credits called **VCUs** (Verified Carbon Units, 1 VCU = 1 tCO₂e). | The program a project joins to get certified credits |
| **PD** | **Project Description** — the document a project developer submits to Verra describing the whole project (baseline, additionality, methodology, monitoring plan, safeguards). This is the *newer* term (VCS v4 renamed it). | The application document |
| **PDD** | **Project Design Document** — the *older/classic* name for that same document (the term comes from the UN's CDM era, and VCS v3 used it). Same purpose as PD; you'll see both names in the wild. | The application document (legacy name) |

## How they fit together (one flow)

```
Verra (standard-setter)
  └─ VCS program (the certification scheme)
        └─ You write a PDD / PD  (the project document)
              └─ 3rd-party validator (VVB) checks it → registered on Verra
                    └─ Monitoring data (e.g. drone scans!) → verified
                          └─ VCUs issued = saleable carbon credits
```

- **VCS** = the *market program*
- **Verra** = the *organization* running it
- **PD / PDD** = the *document* describing your project

## Who is the VVB?

- **SCS Global Services** (US)
- **Bureau Veritas** (France)
- **TÜV SÜD** (Germany)
- **Earthood** (India)

We'd **hire one** (they charge fees; costs vary by project size) for:
1. **Validation** — reviews the PDD before registration
